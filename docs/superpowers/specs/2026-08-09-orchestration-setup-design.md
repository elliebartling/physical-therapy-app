# Multi-Session Orchestration Setup — Design

**Status:** approved, ready for implementation planning
**Date:** 2026-08-09
**Goal:** Give physical-therapy-app the same multi-session orchestration substrate that read-later has, so several Claude/Cursor sessions can work the repo in parallel without colliding.

## Why now

`main` and `finish-v1-parsing` are both at `209de1b` with a clean tree — no work is in flight. This is the cheapest moment to land cross-cutting infra: every day of parallel work done before it is a day of conflicts the protocol would have prevented. The scaffolding lands on `main` first, and `finish-v1-parsing` resets onto the new tip (a fast-forward, since the branches are identical).

## What exists in read-later that doesn't exist here

| Piece | read-later | physical-therapy-app |
|---|---|---|
| Agent briefing | `AGENTS.md` + `CLAUDE.md` symlink | none |
| Orchestration protocol | AGENTS.md §Multi-session orchestration | none |
| Shared build commands | `Makefile` (`gen`/`build`/`test`/`lint`) | none — README says "open Xcode, Cmd-U" |
| Worktree convention | `.claude/worktrees/<name>` | none |
| Merge unit | GitHub PR + CI green gate | no remote at all |
| Xcode project file | gitignored, generated by XcodeGen | **committed** despite `App/project.yml` existing |

## Decisions taken

1. **Merge flow:** push to a private GitHub repo and mirror read-later's PR flow, including CI.
2. **Xcode project file:** gitignore it, regenerate via `make gen`. `project.pbxproj` is the worst merge-conflict file in an Xcode repo and this removes the entire class.
3. **Scope:** full parity in one pass. A protocol whose substrate is half-missing is worse than none — a session that can't run `make test` improvises, which is precisely what the protocol exists to prevent.

## 1. `AGENTS.md` — canonical agent briefing

New file at repo root. `CLAUDE.md` becomes a symlink to it (one file, two names, no drift).

### Sections

**Stack (pinned — do not upgrade without being asked)**
Swift 6.0 with strict concurrency; iOS 26.0 deployment target; SwiftUI + SwiftData; XCTest (**not** Swift Testing); ViewInspector for UI tests; Xcode 26+; project generated by XcodeGen.

**Project file rule (most important)**
`App/PTApp.xcodeproj` is a gitignored build artifact. Never edit or commit it. All target/scheme/build-setting changes go in `App/project.yml`, then `make gen`. If the project file is missing or stale, `make gen` regenerates it.

**Commands** — the make targets from §3.

**Architecture map**
A thin app shell (`App/PTApp/PTAppApp.swift`, `RootView.swift`) over the `PTAppCore` SPM package, which holds five libraries:

- `DataKit` — SwiftData models (`Routine`, `Exercise`, `ExerciseTarget`, `SessionRecord`, `Asset`) and repositories. The dependency root; depends on nothing.
- `ParsingKit` — Vision OCR + routine extraction. Depends on `DataKit`.
- `SessionKit` — `SessionEngine`, clock, audio cues, haptics. Depends on `DataKit`.
- `HistoryKit` — streak and heatmap computation. Depends on `DataKit`.
- `UI` — all SwiftUI surfaces and view models. Depends on all four.

`SessionKit` also ships bundled audio cues via `resources: [.process("Resources")]`.

Five test targets mirror this: `DataKitTests`, `ParsingKitTests` (with `Fixtures` resources), `SessionKitTests`, `HistoryKitTests`, `UITests` (ViewInspector).

**Critical invariants** — sourced from `docs/superpowers/specs/2026-08-09-finish-v1-parsing-design.md`. Phrased file-agnostically where the in-flight refactor will move code, so they stay true before and after:

- `ParsingKit` must not import SwiftUI.
- `import FoundationModels` appears in **exactly one file** in `ParsingKit`, so the framework dependency stays quarantined behind a `@Generable` DTO.
- Swift 6 strict concurrency: every type crossing an async boundary must be `Sendable`.
- No new package dependencies without being asked.
- XCTest only — do not introduce Swift Testing alongside the existing suite.
- Side strings must be one of `both` / `left` / `right` / `alternating`; they feed `Side(rawValue:)` in `ParsedRoutine.toRoutine()` and anything else silently becomes `nil`.
- Heuristic parser defaults must match the LLM prompt: sets 3, reps 10, restSec 30, side `both`. Drift between them makes parse results depend on which extractor won, which is untestable in practice.
- Only OCR failure reaches the UI. Extractor failures fall through to the next extractor.

**Prohibited patterns**

- No `ObservableObject` / `@StateObject` in new code — use `@Observable`.
- No `NavigationView` — use `NavigationStack` / `NavigationSplitView`.
- No force-unwraps (`!`) outside tests.
- No completion handlers where `async/await` works; no new GCD.
- No APIs above iOS 26 without `#available` gating.

## 2. Multi-session orchestration protocol

Goes in `AGENTS.md`, adapted from `orchestrating-parallel-sessions/protocol-template.md` and read-later's production version.

Ellen runs several Claude/Cursor sessions on this repo in parallel. One dedicated session acts as the **Orchestrator** — it sequences merges, assigns file ownership, and tracks every branch in flight. Working sessions follow:

1. **Check merge order before starting or rebasing.** Cross-cutting changes (`App/project.yml`, `Packages/PTAppCore/Package.swift`, `Makefile`, CI, deployment target) land before feature branches; everything else rebases after them. If unsure whether an in-flight branch gates yours, ask before building on stale `main`.
2. **UI-touching PRs embed their screenshots.** Commit evidence screenshots on the branch and embed them in the PR body with `raw.githubusercontent` URLs, before/after where relevant. Ellen reviews from her phone and should never have to hunt through the file tree.
3. **Report back at milestones** — PR opened, CI green, merge conflict, blocked, or finished. Report to the orchestrator session directly if you have session-messaging tools, otherwise end your reply with a clearly-labeled "Status for orchestrator" block: branch name, worktree path, files touched, PR number + state, blockers.
4. **Declare file ownership early.** Hot files: `App/project.yml`, `Packages/PTAppCore/Package.swift`, `App/PTApp/RootView.swift`, `Sources/UI/DesignSystem/`, `Sources/SessionKit/SessionEngine.swift`, `AGENTS.md`, `Makefile`. Also declare `ParsedRoutine` — it is the contract between `ParsingKit` and `UI`, so a change to its shape breaks both sides even though the file is small.
5. **Two contended resources, one at a time each.**
   - **The simulator.** Concurrent sessions stomp each other's installs.
   - **The physical Apple Intelligence device.** Foundation Models verification needs real hardware and, unlike the simulator, it cannot be duplicated. Claim it explicitly and release it explicitly.
6. **Stay in your own worktree.** Never edit the main checkout or another session's worktree unless the orchestrator hands that work to you.
7. **Don't merge your own PR** unless Ellen or the orchestrator says to. Merges are sequenced so downstream rebases cascade in the right order.

### Sub-agent model policy

- Implementation and code-review agents run **Opus** (`model: "opus"`). Never let them fall through to a default, and don't downgrade for cost unless Ellen asks in that session.
- Research / web-survey agents may run **Sonnet** or better.
- Trivial one-shot lookups may use any small model.

### Worktree convention

Session worktrees live at `.claude/worktrees/<branch-name>`, gitignored. Unlanded diffs get backed up to `.claude/backups/` before any worktree is pruned.

## 3. `Makefile`

Adapted from read-later's, so every session and CI run the identical commands.

```make
SHELL := /bin/bash
.SHELLFLAGS := -eo pipefail -c
```

This guard is not cosmetic. Without `pipefail`, `xcodebuild ... | tail` reports the exit status of `tail` only, so a broken build exits 0. This shipped a false-green CI run in read-later.

Variables: `SCHEME ?= PTApp`, `DESTINATION ?= platform=iOS Simulator,name=iPhone 17 Pro`.

Targets: `bootstrap` (verify `xcodegen` present, warn if `swiftformat` absent), `gen`, `open`, `build`, `test`, `lint`, `format`, `clean`. `gen` depends on `bootstrap`; `build`, `test`, and `open` each depend on `gen`, so a stale or missing project file can never reach a build.

**XcodeGen invocation:** the spec is at `App/project.yml`, not the repo root, so `gen` must pass `--spec App/project.yml --project App` (or `cd App`). This differs from read-later, where the spec sits at the root.

### Open question for the implementation plan

`make test` must run all five test targets, but `App/project.yml` has no `schemes:` block, so XcodeGen auto-generates one scheme per target — and the `PTApp` app scheme will not pick up the package's test targets. The existing plan doc works around this with per-package schemes:

```
xcodebuild test -project App/PTApp.xcodeproj -scheme ParsingKit \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' \
  -only-testing:ParsingKitTests
```

So `make test` most likely iterates the package schemes. **The implementation plan must empirically verify which invocation actually runs all five suites, and assert on the reported test count — not assume.** A `make test` that silently tests nothing is strictly worse than having no `make test`, because it manufactures false confidence and CI would go green on it.

### swiftformat

Not installed on this machine and the repo has no swiftformat config. `lint` and `format` print an install hint and skip cleanly when the binary is absent. Do **not** copy read-later's `swiftformat --lint . || true` — that converts a genuine lint failure into a pass.

## 4. GitHub repository and CI

### Repository

```
gh repo create elliebartling/physical-therapy-app --private --source=. --remote=origin --push
```

Private. `gh` is already authenticated as `elliebartling` with `repo` and `workflow` scopes. **This step is confirmed with Ellen before it runs** — it is the only step that pushes code off the machine, and publishing is not trivially reversible.

### `.github/workflows/ci.yml`

Mirrors read-later's, carrying its hard-won cost and correctness lessons:

- **Triggers:** `pull_request` plus `push` to `main` only. Not `push: ["**"]` — that pair bills every PR-branch push twice, under two concurrency groups where neither cancels the other. macOS runner minutes bill at 10× on private repos.
- **`paths-ignore`:** `**.md`, `docs/**`, `LICENSE` — doc-only changes skip the Mac job entirely.
- **Concurrency group** with `cancel-in-progress: true`, so superseded runs die.
- **`timeout-minutes: 20`** — a hung build bills 10 minutes for every wall minute.
- **`defaults.run.shell: bash`** — explicit bash runs with `-eo pipefail`; the implicit default shell does not, and that is what produced the false-green run.
- **Steps:** checkout → `brew install xcodegen` → `make gen` → pick an available simulator dynamically (don't hardcode a device that may not exist on the runner image) → `make test` with `CODE_SIGNING_ALLOWED=NO`.

CI invokes the make targets rather than raw `xcodebuild`, so local and CI behavior cannot drift.

## 5. Repository changes

- `git rm -r --cached App/PTApp.xcodeproj` — untracks it, keeps it on disk.
- `.gitignore` gains: `App/PTApp.xcodeproj/`, `.claude/worktrees/`, `.claude/backups/`.
- `README.md` updated — replace "open in Xcode / Cmd-U" with the make commands, and point at `AGENTS.md`.
- `docs/superpowers/plans/2026-08-09-finish-v1-parsing.md` — its "Running tests" section hardcodes `xcodebuild test -project App/PTApp.xcodeproj`, which breaks on a fresh clone once the project file is untracked. Reroute through `make`.

## Success criteria

1. A fresh clone can run `make gen && make test` and get a real, non-empty test result.
2. `App/PTApp.xcodeproj` no longer appears in `git ls-files`.
3. `AGENTS.md` and `CLAUDE.md` both resolve to the same content.
4. A PR against the new repo triggers CI, and CI fails when a test fails (verify with a deliberately broken commit — a green-only check proves nothing).
5. `finish-v1-parsing` sits cleanly on top of the new `main`.

## Out of scope

- Vendored domain skills (`.agents/skills/`) — read-later has them; PT app doesn't need them yet.
- A status-board Artifact — worth adding once more than two sessions actually run concurrently.
- TestFlight / release shipping workflow.
